# 슬라이딩 윈도우 & 차선 계수 소스 정리

차선인식(lane detection)의 슬라이딩 윈도우 탐색과 다항식 계수 계산 관련 소스 위치 및 설명.

## 핵심 요약

- 모든 차선 로직은 아래 두 파일에 있음:
  - 헤더: `src/ws_cam2/src/lane_detection/include/lane_detection/LaneDetection.hpp`
  - 구현: `src/ws_cam2/src/lane_detection/src/LaneDetection.cpp`
- **`runSlidingWindow` / `computeSlidingWindowBase`는 정의는 있으나 현재 파이프라인에서 호출되지 않는 legacy 코드**임.
- 실제 실행 경로는 `DetectFromMask` → `findPixelsFromMask` (슬라이딩 윈도우 아님) → `fitPolynomial` → `calcLaneCoeffs` (3차 가중 최소자승) → 칼만 스무딩.

## 2. 차선 다항식 계수 계산

3차(cubic) 다항식, 모두 `cv::Vec4d` 반환. 계수 순서 = **[x³, x², x, 1]** → 차량 좌표계에서 횡방향 y.

| 함수 | 위치 | 비고 |
|---|---|---|
| **`calcLaneCoeffs()`** ← 현재 사용 | `.cpp:4467-4533` (선언 `.hpp:714`) | 가중 최소자승. 정규방정식 A(4x4)=XᵀWX, b=XᵀWy, 대각 정규화 `kLambda=1e-9`, `cv::solve(..., DECOMP_QR)`(4527행). 차량 근거리 점에 큰 가중치(4484행). `bevPixToVehicle`로 BEV 픽셀→차량 좌표 변환 |
| `calcLaneCoeffs_org()` | `.cpp:4419-4463` (선언 `.hpp:715`) | 구버전. 가중 설계행렬 직접 풀이, `cv::solve(..., DECOMP_SVD)`(4457행) |
| `fitPolynomialFromSamples()` | `.cpp:3357-3383` (선언 `.hpp:767`) | 칼만 샘플 기반 3차 fit, `DECOMP_SVD`(3377행), `config_.kf_sample_x_m` 사용 |
| `fitLaneGeometry()` | `.cpp:3385-3416` | `LaneGeom`(y0/theta/kappa/kappa_dot 형태) 반환, `DECOMP_SVD`(3405행) |
| `fitQuadratic` (로컬 람다) | `.cpp:2677-2695` | 2차 가이드 fitter, `DECOMP_SVD`(2692행), `cv::Vec3d` |

### 오케스트레이터: `fitPolynomial()`
`.cpp:2961-2999` (선언 `.hpp:698`). `calcLaneCoeffs(pixels_L_)` / `calcLaneCoeffs(pixels_R_)` 호출(2967-2968행) → `coeffs_fit_L/R` 저장, `detected_fit_L/R` 설정 → `coeffs_L/R`로 복사. `Detect()`(164행)와 mask 경로(288행)에서 호출됨.

## 계수 값 실시간 확인 (프레임 뷰어)

`cam2_yolopv2.launch.py`에 `bag_path`를 넘기면 프레임 단위 뷰어의 `Lane Values` 패널에서 아래 계수/상태를 프레임마다 눈으로 확인할 수 있다 (자세한 조작은 `lane_bag_verify_guide.md` 참고).
- `coeffs_fit_L/R` : `calcLaneCoeffs()` 직후 raw 3차 계수
- `coeffs_L/R` : 칼만 스무딩 후 최종 계수
- `state_L/R`, `pixel_count`, `rmse_fit_m`, `span_m` 등 판정 근거 값

계수가 `[0,0,0,0]`이면 미검출(NODET), `coeffs_fit`은 값이 있는데 `coeffs_L/R`만 0이면 게이트(validateAndSmooth) 탈락으로 해석한다.
